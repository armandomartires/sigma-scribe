# S15.3 — Word mode trial + gate (v1.5.3)

Plan §12.3 ("word mode spike + gate", renumbered to v1.5.3 by decision 51), decision 54. Emulator and CI only (decision 48).

## Gate (written before any measurement; commit `GATE` below)
Word mode is **kept on by default only if both hold**; otherwise it ships **behind an off-by-default setting** (Settings → Handwriting → Word mode (experimental)) or is dropped if it is not usable at all:

- **G1 accuracy:** character error rate (CER, edit distance / reference length) of the top-1 word **≤ 15 %** on held-out synthetic words written in the two **fonts never trained on** (Handlee, Delius) **after 1 enrolled sample per character** (the plan's "held-out enrolled ink"), with the built-in EN/FR/PT lexicon that would ship.
- **G2 speed:** **≤ 1 s per word** (p95) on the i.MX6 SoloLite estimate (x86 time × the A9 factor used in S15.2: ≈ 5.5×, i.e. ≤ 180 ms p95 on the CI/emulator x86).
- Also reported, not gating: CER without enrolment, CER on unseen jitter of the training fonts, open-vocabulary CER (no lexicon), word accuracy, top-5 word accuracy.

Drop instead of flag if: CER > 40 % or p95 > 3 s on the A9 estimate (not worth a setting).

## Approach (no new dependencies)
The plan named a small LSTM-CTC run with tract. A trial of that needs a training pipeline and a new runtime dependency (tract) for 1–2 M parameters; this trial first measures the cheap route that reuses the v1.5.2 character network, so the gate is answered with what exists:
- **Over-segmentation:** cut candidates at gaps and ink-density minima along x; each run of 1–4 pieces (≤ 1.1 line heights wide) is a character hypothesis, moved into a box (same baseline, same units as Letters) and scored by the v1.5.2 network (with the user's samples).
- **Lexicon decoding:** dynamic programming aligns each lexicon word to the cuts (mean log-probability per letter; the first letter may be a capital); open-vocabulary Viterbi as a fallback when nothing in the lexicon fits. Lexicon = built-in common words (EN/FR/PT, `assets/hwr/words-*.txt`, own list) + words in the user's notes.
- **Synthetic words for testing:** glyph skeletons of the same OFL fonts placed side by side with random spacing (including touching letters) and the S15.2 jitter.

## Results (CI log step "Handwriting figures", `tools/hwr-train/tests/words.rs`, `--nocapture`)
Built-in lexicon (EN 291, FR 192, PT 182 own words), 150 held-out words per set, x86 times (A9 ≈ × 5.5):

| Set | CER | Note |
|---|---|---|
| Training fonts, new jitter | 13.7 % | top-1 word 81 %, top-5 93 %, p95 23 ms |
| Handlee, no enrolment | 24.0 % | |
| Handlee, 1 sample/char (**G1**) | **26.6 %** | p95 33 ms |
| Delius, no enrolment | 19.6 % | |
| Delius, 1 sample/char (**G1**) | **24.3 %** | p95 36 ms |
| Open vocabulary (no lexicon) | ≈ 86–100 % | not gating |

`GATE G1 FAIL (worst 28.3 %), G2 pass (33.6 ms ≈ 0.19 s on the A9)` in one run; the figures move by about ±2 points between runs.

**Verdict: no-go on G1** (worst enrolled held-out CER ≈ 24–28 % > 15 %), **G2 passes** with a wide margin, and it is above neither drop line (40 %, 3 s). So word mode **ships behind an off-by-default setting**: Settings → Keyboard & input → Handwriting → **Word mode (experimental)** (`ink_words=`, decision 54). It is not dropped because it does help on joined-up letters (below) and costs nothing when off. Why it misses: the character net was trained on isolated glyphs, so cuts through joined strokes give low-confidence pieces; a sequence model (the plan's LSTM-CTC, needs tract) is the route to ≤ 15 %, left for after v1.6.

## Follow-up: decoder tuning (2026-10-26)

Measured where word errors come from (300 words per held-out font): the cuts could form the right word in all but one case, so every error is the decoder choosing a worse lexicon word, and about two thirds of those have the wrong number of letters. Enrolment made words worse because the nearest-sample boost of `Recogniser::probs` also lifts pieces that are half a letter or two letters. Changes:
- The word decoder reads pieces with `Recogniser::net_probs`: the network with the output layer fine-tuned on the user's samples, without the nearest-sample boost (letters keep it).
- A letter-width prior: each hypothesis' ink width against the character's typical width in the training fonts (`assets/hwr/widths.txt`, `hwr-train widths`), a Gaussian on ln width, weight 0.5.
- `LETTER_BONUS` 8 → 7.

`hwr-train words` / `free`, same sets as above:

| Set | Before | After |
|---|---|---|
| Training fonts, new jitter | 15.3 % | 14.3 % |
| Handlee, no enrolment / 1 sample per char (**G1**) | 24.6 % / 24.1 % | 17.1 % / **14.0 %** |
| Delius, no enrolment / 1 sample per char (**G1**) | 27.2 % / 27.2 % | 25.3 % / **24.3 %** |
| Free area, touching letters, enrolled (Handlee / Delius) | 36.7 % / 41.3 % | 34.6 % / 37.4 % |
| Free area, printed | | unchanged |

G1 still fails on Delius (worst ≈ 24 %). A weight of 1 for the width prior gives Delius about 1.5 points more but costs the training fonts about 3. The next step is the character network itself: it was trained on whole isolated letters and has no way to say "this piece is not a letter".

## Boxless panel (user design change, decision 55)
During the sprint the user asked for a Boox-style panel (reference photo only, nothing copied): a full-width candidate bar (‹ › paging, plain words separated by thin rules, × close), a 3 × 4 grid of outlined rounded keys on the left (⇄ Letters/Draw, ⌫, ↵ / , . ? / 123 ! @ / globe, a 2-wide space; Lucide icons arrow-left-right, delete, corner-down-left, globe, chevron-left/right, space), and a **large blank writing area** on the right (no boxes, baselines or frame). Pure black and white, DU-safe, targets ≥ 44 px, portrait and landscape.

Because word recognition missed the gate, the free area **segments the ink into characters automatically** (`crates/hwr/src/free.rs`) and reads each with the v1.5.2 network:
- strokes are grouped by x-overlap, pieces closer than 0.03 line units are joined, the line unit and baseline come from medians; a gap > 0.38 line units types a space;
- a piece wider than 0.8 line units (touching letters) sends that word to the lexicon decoder above; with Word mode on every word goes to it;
- up to 4 alternatives (least sure character swapped for its runner-up, then lexicon runners-up); a lexicon word among them beats a non-word top reading; 123 restricts to digits, the globe cycles the letter set (all → EN → FR → PT);
- read 1.2 s after the last stroke; a space follows a word.

**Letter boxes** (v1.5.2) stay as a fallback setting (`ink_boxes=`, off by default). Train opens the box enrolment and returns to the free area.

Free-area figures (`free` in the trainer; printed = letters with gaps; 150–300 phrases per set):

| Set | CER | exact | in candidates | p95 (x86) |
|---|---|---|---|---|
| Training fonts, printed | 7.7 % | 65 % | 79 % | 3 ms |
| Handlee printed, no enrolment / 1 sample per char | 28.2 % / 24.5 % | 17 % / 23 % | | 3–4 ms |
| Delius printed, no enrolment / 1 sample per char | 20.6 % / 19.0 % | 21 % / 22 % | | 3–4 ms |
| Touching letters, enrolled (Handlee / Delius) | 35.5 % / 36.4 % | | | 60–71 ms |

All well inside G2. Printed writing is the recommended way in; the device pass will tell how real hands compare with the synthetic fonts.
