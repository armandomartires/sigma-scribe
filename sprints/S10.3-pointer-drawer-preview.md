# S10.3 — v1.0.3: Pointer lag fix, drawer in preview

**Status:** ✅ DONE (passed on the Forma, confirmed 2026-10-27); built 2026-10-22 (branch v1.0.3) · **Release:** v1.0.3 · **Approved:** 2026-10-22 · **Depends on:** v1.0.2

## A. Pointer lag (decision S10.3-D2)
Finding (1.0.1 device log): `perf pointer: gl16` p50 606 ms, p95 1091 ms; typing p95 rose to ~187 ms (66–94 ms before the pointer). Cause: every move was a GL16 update (slow waveform, collides with typing updates on the EPDC) and every 20th move called `fbink_wait_for_complete` on the input thread.
- Moving pointer: `Refresh::Pointer` → FBInk **DU**, submitted and never waited for.
- Hide (3 s idle, typing, touching): one non-flashing **GL16** cleanup (`Refresh::PointerCleanup`) over the union of the pointer's path since the last cleanup, clearing DU trails.
- No pointer path waits for completion (`sg_wait` is no longer called anywhere on the input loop); a key or touch hides the pointer and is handled first.
- All regions ≥ 16×16. Throttle 150 ms, hide 3 s (unchanged).
- Device log: `perf pointer: du WxH submit N ms` (every 20th move), `perf pointer: gl16-cleanup WxH submit N ms` (each hide), and at exit `perf pointer: N updates, p50 … p95 … max … ms` (app-side event-to-submit time) beside the typing `perf:` summary.

## B. Drawer in preview (decision S10.3-D1, amends S5-D1)
- `drawer_allowed()` = write mode **or** preview; false on sheets (Files, Options, Graph, Help, rename). Used for visibility, layout, taps, the title-bar pane-button highlight and scratch focus.
- Preview with the drawer open: the preview page is laid out in the space beside the drawer (re-laid out when panes open/close, keeping the shown source line).
- Contents: the preview's rendered headings; a tap jumps to the preview page holding that heading (pushes Back history).
- To-dos: a checkbox tap toggles with the same buffer edit / atomic write + reindex as write mode, then the preview is rebuilt on the same page. Deliberate exception to read-only preview (decision 12). Tapping a to-do's text opens it as in write mode.
- Scratch: editable in preview; keys go to the scratch only while it has focus; the note itself stays read-only.
