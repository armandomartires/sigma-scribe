# S15.4 — Gestures (v1.5.4)

Plan §12.3 ("gestures: scratch-out delete, caret tap, line join"), decision 56. ✅ DONE (accepted complete 2026-10-27). Built with the emulator and CI (decision 48). Last sprint of the handwriting wave; v1.6 waits for the user's go.

## What
All in the Write panel; geometry only (`crates/hwr/src/gesture.rs`), no model, < 0.1 ms per stroke.
- **Scratch-out** (a zig-zag of ≥ 3 horizontal turns, wider than tall, path ≥ 2.5 × its width):
  - over pending (not yet read) ink in the free area: erases every stroke in its x-range (the area holds one line, so dots and descenders go too); nothing is typed;
  - over an empty area: deletes the last reading (the word and its space) if it was just typed, otherwise the word before the caret;
  - in Draw: erases the strokes whose box it crosses.
- **Flick left** (one flat stroke, ≥ 0.35 area heights long, height ≤ 20 % of its width, no turns): Backspace; at a line start it **joins the line** to the one above. Pending ink is read first.
- **Flick right**: Space.
- **Caret tap**: a tap on the note above the panel reads pending ink, then moves the caret there; the panel stays open (touch and the emulator's tap event).
- A short dash, an "8", a "z" and a "w" stay ink (unit tests).

## Tests
- `crates/hwr/src/gesture.rs` unit tests (scratch, flicks, letters that must not trigger).
- `app/tests/gestures.rs`: scratch over ink / last reading / previous word, flick join and space, caret tap, Draw scratch.
- Emulator `tests/emu/v1.5.4-gestures.script`; screenshots `docs/screenshots/v1.5.4/` (before/after pair `before-scratch.png` / `after-scratch.png`).

## Limits
- False triggers on real handwriting cannot be measured with the synthetic ink (font skeletons have no stroke order); the device checklist asks for it. The thresholds are constants in `gesture.rs`.
- No gesture to insert a newline or select text (↵ and the note's own selection do that).
