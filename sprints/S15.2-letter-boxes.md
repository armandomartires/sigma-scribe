# S15.2 — Letters: per-character boxes (v1.5.2)

Plan §12.3 character mode, decisions 31 (opt-in local samples), 49 (§12 accepted), 51 (renumbered to v1.5.2) and 53. Emulator and CI only (decision 48); device checks in `docs/device-checklist-prerelease.md` → "Letters (v1.5.2)". Ships together with S15.2a (wiki links follow rename/move, decision 52).

## What it does
- The Write panel gets a **Letters** button (Draw ↔ Letters). Letters shows **5 square boxes** (6 in landscape) with a dotted baseline at 70 %, a candidate row and the buttons Draw, Undo, Space, Erase, Return, Train, Done.
- Write one character per box. The box is read **0.8 s after the last stroke**, or at once when a stroke starts in another box (so writing box to box is not slowed down). The best character is typed **at the caret**, the box empties, and the **5 best candidates** show as chips (the first, filled, is what was typed). Tapping another chip **replaces** the letter just typed. Space / Erase / Return type a space, delete one character, a new line (each reads a pending box first). Done closes the panel.
- Ink is the same as Draw: pure black, live DU segments (`Refresh::Ink`, or A2 when Fast ink is on); a read redraws the panel with the normal partial refresh (no extra GL16 pass while a box is pending).
- **Train (enrolment, opt-in):** one big box with the prompt "Write: a (1/126, n saved)"; Save stores the ink as a sample of that character and moves on; Skip moves on; Done goes back to Letters. Samples go to **`notes/.handwriting/samples.txt`** (plain text, box units, one line per sample; hidden from Files like `.ink/`), never anywhere else. Settings → Keyboard & input → Handwriting → **My handwriting: Samples: n · Delete** removes the file (and the folder if empty).
- Charset (126): a–z, A–Z, 0–9; FR/PT accents à â ç é è ê ë î ï ô ù û ü œ æ á ã õ ó í ú and their capitals; `. , ; : ! ? ' " - ( ) / @ & % + = * # € « »`.

## Recogniser (`crates/hwr`, no dependencies, AGPL)
- **Features (406):** ink segments resampled every 0.02 box units; undirected direction (4 bins, soft) deposited bilinearly on a 6×6 grid **in box coordinates** (keeps size and position: `.` vs `,` vs `'`, `o` vs `O`) and on an 8×8 grid in the ink's **own bounding square** (min side 0.15, keeps shape); each block square-rooted and L2-normalised; plus the bounding box (6 values).
- **Network:** 406 → 192 ReLU → 126 softmax, **int8 weights with one scale per row** (104,876-byte file `assets/hwr/default.hwr`, `include_bytes!`), f32 activations. ~102 k multiply-adds per character.
- **User samples:** the output layer is fine-tuned on the samples (20 passes, SGD, pulled back to the default weights with L2), on a **background thread** when the model is first used or after Train → Done; the plain model answers until it is ready. A nearest-sample term (σ 0.45, weight 1.5) is blended in. Tuned with `examples/tune.rs`.

## Default model: synthetic ink only (`tools/hwr-train`, not shipped)
- Every glyph of 10 OFL fonts (9 handwriting-style fonts from Google Fonts + Atkinson Hyperlegible; list and licences in `tools/hwr-train/fonts/`) is rasterised into a 96-px box at its baseline, **thinned to a one-pixel skeleton** (Zhang–Suen) and turned into segments. Each sample gets random **jitter**: size 0.7–1.2, aspect ±20 %, slant −0.35…+0.25, rotation ±8°, offset ±8 %, plus a smooth elastic wobble (4 sine waves ≤ 0.018).
- 60 samples per character per font (75,540), 12 epochs SGD + momentum, seeded: `cargo run -p hwr-train --release -- train` rebuilds the **byte-identical** file (checked: sha256 `9fa3baedc5a0eefa9e0ad90065e5e872dcd01a31a711d6e3793e365c77caf428`, 2.5 min on an i5-6300U). No real handwriting from anyone was used.

## Measured (held-out synthetic, emulator/CI)
`cargo run -p hwr-train --release -- eval` (CI runs a smaller copy, `tools/hwr-train/tests/heldout.rs`, with floors):

| Set | n | top-1 | top-5 | top-1, case folded* |
|---|---|---|---|---|
| Training fonts, unseen jitter (seed 1001) | 12,590 | **97.4 %** | 99.98 % | 98.2 % |
| Two fonts never trained on (Handlee, Delius) | 5,040 | **82.5 %** | 98.4 % | 91.4 % |
| Handlee, after 1 enrolled sample per character | 2,520 | 78.0 → **81.8 %** (3/char: 87.2 %) | 97.7 % | 89.1 → 91.5 % |
| Delius, after 1 enrolled sample per character | 2,520 | 87.3 → **90.0 %** (3/char: 92.5 %) | 99.2 % | 94.6 → 95.2 % |

\* `o/O/0`, `c/C`, `s/S`, `x/X`… counted as right; the candidate row fixes these with one tap. The unseen-font rows are the closest synthetic stand-in for a new hand; real handwriting will differ (device checklist).

**Latency (x86, i5-6300U 2.4 GHz, one core):** 168 µs per character end to end (features + network + ranking; 145 µs network only). Fine-tuning on 126 samples: 0.30 s.

**i.MX6 SoloLite estimate (Cortex-A9, 1 GHz, VFPv3/NEON, one core):** the network is a dependent multiply-add chain per row (x86 measures ≈ 4 cycles per MAC, the addss latency). On the A9 the VFP multiply-accumulate chain is ≈ 8–10 cycles, so ~102 k MACs ≈ **0.8–1.0 ms**, plus features and ranking: **≈ 1–3 ms per character**, far below the 0.8 s read pause. Fine-tuning ≈ 5–6× the x86 time: **≈ 1.5–2 s for 126 samples** (≈ 5 s for 3 per character), on a background thread. No NEON code yet (not needed at these times).

## Size
Device binary grows by the model (104,876 bytes) plus the recogniser code; measured on the CI armv7 build: see CHANGELOG 1.5.2.

## Decisions
- **S15.2-D1:** one network for all 126 characters (no per-language model); the candidate row is the fix for the confusable pairs.
- **S15.2-D2:** box coordinates are part of the features (punctuation and case depend on size/position); the baseline guide in every box makes that work.
- **S15.2-D3:** enrolment stores raw ink, not features, so a later model can re-learn from the same file; plain text so the user can read or delete it.
- **S15.2-D4:** the training fonts live in the repo (OFL, with licences) so CI can measure on the same held-out sets; they are not in the package.
- **S15.2-D5:** a recognised letter is typed straight into the note (undo with Erase or a chip), not collected for a separate Insert.

## Tests
- `crates/hwr` unit tests: charset, features keep position/shape, model round trip, samples text, user samples pull their character up.
- `tools/hwr-train/tests/heldout.rs` (CI): floors top-1 ≥ 95 % / top-5 ≥ 99 % on unseen jitter, top-1 ≥ 78 % / top-5 ≥ 97 % / folded ≥ 88 % on unseen fonts, enrolment must help, latency < 20 ms/char.
- `app/tests/letters.rs`: DU live ink, read after the pause or the next box, candidates replace, Space/Erase/Return, Train writes `samples.txt`, Delete removes it, Files never lists it.
- Emulator `tests/emu/v1.5.2-letters.script` (`ink-box` command: strokes in box units): writes `o l x .` and `c`, picks `C`, erases, enrols an `a`, deletes the samples. Screenshots `docs/screenshots/v1.5.2/`.
