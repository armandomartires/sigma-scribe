# S15.2a — Rename / move rewrites wiki links (part of v1.5.2)

Fix for the 1.5.1 known issue "renaming a note drops other notes' backlinks" (decision 52). Ships in 1.5.2 (no separate version).

- `links::rewrite(text, before, moved)`: every `[[target]]` / `[[target|alias]]` that resolved, among the notes **before** the change, to a moved note is rewritten to its new name. The form is kept: a path stays a path (`[[drafts/old]]` → `[[drafts/new]]`), a bare name a bare name, an `.md` / `.txt` ending stays, an `|alias` stays as written, a `#heading` part stays (the resolver does not use headings yet; the text is kept intact). Fenced and inline code are left alone.
- `Library::rename` and `Library::move_to` call it for every note and the scratch pad, for a note or every note inside a renamed / moved folder (path links follow a folder move; bare names stay).
- The app saves the open note and the scratch pad before, and takes the rewritten text back afterwards (undoable, caret kept).
- Tests: `links::tests::rewrite_keeps_form_alias_heading_and_skips_code`, `library::tests::rename_and_move_rewrite_wiki_links_elsewhere`; emulator `tests/emu/v1.5.2-relink.script` (rename from Files, open note follows).
